# Task 04 - Estate Lot Bulk Import And Manual Form Reduction

## Priority
P1

## Status
Implemented (FE) - DXF-first flow is default, manual entry is simplified with advanced fields gated.

## Implementation Notes (2026-02-27)
- Updated `src/components/admin/estates/EstateLotsCrud.tsx` to position DXF import as the primary path.
- Manual lot entry now surfaces the agreed core fields first: zoning, lot type, overlays, lifecycle stage, and road facing.
- Technical/manual-heavy fields (geometry, S1-S4, frontage GeoJSON, lot metadata overrides) are hidden behind an `advanced fields` toggle.
- DXF import options now show a simplified default form, with importer internals under `advanced import options`.

## Source Feedback
- Manual lot-by-lot entry is not viable.
- Client expected bulk upload (CSV/spreadsheet) as primary workflow.
- Estate users should not need to manually author raw GeoJSON and dozens of technical fields.

## Scope
- Confirm and implement primary bulk import flow for estates.
- Keep manual form as fallback/edit mode, but reduce it to a minimal set of useful fields.
- Move geometry-heavy fields behind import or advanced mode.

## Decisions Made To Unblock
1. Use DXF import as the primary estate onboarding workflow for MVP.
2. Defer CSV/spreadsheet lot import to a separate follow-up task (not blocking this phase).
3. Keep manual lot entry as fallback/edit mode only.
4. Treat DXF-derived geometry and side-length data as system-managed (not standard estate inputs).
5. Use Mitch's 3-group model for estate-facing lot fields:
   - Auto from DXF: boundary polygon, frontage line, area, block/section/division, address, S1-S4.
   - Must be entered manually: zoning, lot type, overlays, lifecycle stage, road facing.
   - Keep but hide by default: setbacks/height/FSR and related advanced overrides.

## MVP Estate Lot Field Strategy
1. Primary input path: DXF upload and derived defaults.
2. Manual required fields (estate-facing): zoning, lot type, overlays, lifecycle stage, road facing.
3. Advanced fields remain in the data model but are hidden behind an advanced section.
4. Raw GeoJSON/frontage coordinate editing is hidden from standard estate workflows.
